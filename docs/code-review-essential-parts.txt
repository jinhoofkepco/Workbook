전체 구조
--------
1. JSON 문제집 가져오기
   workbook zip/json -> WorkbookImportService -> Room DB 저장

2. 문제 풀이
   PracticeViewModel -> PracticeScreen -> HandwritingCanvas/AnswerInputControls

3. 채점
   SubmitPracticeAnswerUseCase -> DefaultGradingEngine -> PracticeAttemptEntity / AttemptInputLogEntity 저장

4. 마스터 모드
   MasterScreen / MasterViewModel -> 기존 풀이 기록 확인, 정답 수정, 노트/채점

5. 휴대폰 viewer
   ViewerServer -> 같은 네트워크 HTTP viewer -> 완료된 풀이 및 현재 화면 조회

1) 데이터 모델
파일:

중요 클래스:
- ProblemEntity: 문제 본문, 이미지, 이미지 레이아웃 JSON 저장.

검증 포인트:

- ProblemEntity.imageCropRectJson에 imageDisplayJson, gradingPolicy, solutionText, teacherMemo, answerNote가 합쳐져 저장된다.

우선 검증해야 할 사용자 시나리오
-----------------------------
1. 보기 버튼이 많은 문제
   - ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅇ이 모두 보이는지.
   - 줄바꿈 후 버튼 터치 영역이 정상인지.

2. 클릭 순서가 중요한 보기 문제
   - 나 -> 는 -> 황 -> 소 -> 수 -> 학 -> 신 순서로 누르면 답칸이 같은 순서인지.
   - 중간 항목을 다시 눌러 해제하면 해당 항목만 빠지는지.
   - 다시 누르면 맨 뒤에 붙는지.

3. 분수 입력 문제
   - 답에 "/"가 필요한 문제에서 공백 / "/" 버튼 표시.
   - 공백 버튼으로 대분수 입력 가능.
   - 직접채점/비활성 답칸에서는 버튼이 나오지 않는지.

4. 수동채점 문제
   - gradingPolicy.mode = manual_review 또는 answerType = MANUAL_REVIEW일 때 제출 후 검토 필요로 기록되는지.
   - solutionText가 문제 아래/마스터 검토에서 표시되는지.

5. 필기 저장 문제
   - 문제 이미지 위에 필기 후 제출.
   - 마스터 모드에서 같은 위치에 필기가 나타나는지.
   - 사진 합쳐 저장 시 필기가 아래로 밀리지 않는지.

6. Viewer
   - 학생이 새 문제를 풀고 제출하면 viewer 목록에 표시되는지.
   - refresh 연타 시 앱이 종료되지 않는지.
   - 현재 화면 조회가 앱 부하를 만들지 않는지.


검증 시 특히 볼 개선 후보
-----------------------
1. JSON import schema가 여러 곳에 흩어져 있다.
   - imageCropRectJson 안에 display, gradingPolicy, solutionText, notes를 함께 넣는 구조가 디버깅을 어렵게 한다.
   - 장기적으로 ProblemEntity에 별도 컬럼을 두거나 typed metadata 객체를 두는 것이 안전하다.

2. PracticeScreen.kt가 지나치게 크다.
   - Answer input, toolbar, worksheet, master review UI가 한 파일에 밀집되어 있다.
   - AnswerInputControls, InlineChoiceSelector, Worksheet area, MasterAnswerArea는 별도 파일로 분리할 후보.

3. 선택지 입력 로직이 UI 파일에 있다.
   - toggleInlineChoiceAnswer 같은 입력 정규화 함수는 ViewModel 또는 별도 utility로 이동하면 테스트하기 쉽다.

4. 수동채점 판정 조건이 여러 레이어에 중복된다.
   - import, grading engine, UI 표시에서 manualReviewRequired/skipAutoGrading/manualGradingRequired를 각각 해석한다.
   - 하나의 policy resolver로 모으는 편이 안전하다.

5. ViewerServer가 HTML/JS/CSS 문자열을 Kotlin 파일 안에 크게 포함한다.
   - 유지보수와 오류 검증이 어렵다.
   - assets 파일 또는 template 분리 후보.

6. 좌표계 변환 검증이 중요하다.
   - 문제 이미지 transform, border resize, handwriting vector, merged image 저장 사이의 기준 좌표가 달라지면 필기가 밀린다.
   - 이 부분은 자동 테스트 또는 debug overlay가 필요하다.
